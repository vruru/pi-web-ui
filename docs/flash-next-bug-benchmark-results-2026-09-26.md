# Flash Next 公开缺陷对照实测：2026-09-26

本次共 46 题。A 单次生成通过 43/46；B 增加独立复核与测试确认后的返工，通过 44/46；C 只根据测试失败返工、不做独立复核，通过 44/46。这轮没有显示独立复核相对于测试驱动返工的额外收益。

## 方法与数据来源

- [QuixBugs](https://github.com/jkoppel/QuixBugs/tree/4257f44b0ff1181dedaedee6a447e133219fcebf)：全部 40 个 Python 测试模块。
- [BugsInPy](https://github.com/soarsmu/BugsInPy/tree/master/projects/youtube-dl/bugs)：youtube-dl 历史缺陷 1、3、4、6、7、10，类别在模型运行前选定。
- 全部 46 题在模型运行前验证：原缺陷文件失败、官方修复文件通过。模型只看到缺陷代码、相关辅助定义和任务契约，不看到官方修复代码。
- 采用同初稿配对；B、C 从同一份 A 初稿出发，最多两次返工。测试固定，按原始收集顺序偶数项提供反馈、奇数项保留判分。
- 固定 pennyroyal，思考开启，单次输出上限 32,768。两路并发；不固定采样种子；每题仅一次初始生成。所有修复代码由 Flash Next 生成，付费模型仅参与评测设计检查。
- B 使用已部署 MCP 的 generate/review/revise 流程；复核每次新上下文，不传作者内部思考。只有实际反馈测试失败才授权返工。通过反馈测试后保留候选，不执行未验证的复核建议。
- C 使用相同反馈信息进行新调用返工，不接收复核报告。B 和 C 的角色提示模板不同，测试的是当前工作流整体，而非严格单变量提示实验。

## 两个关键案例

### youtube-dl-1：真正起作用的是测试失败反馈

初稿误把布尔值需求理解为过滤表达式中的 true/false 关键字，字段值为 False 时仍未正确处理。独立复核报告认为没有可操作问题，但实际测试 `test_match_str` 失败。B 收到失败断言后修复，C 不经过独立复核、只收到同一失败信息也修复。不能把这一题的改善归因于独立复核。

### youtube-dl-6：复核没有发现保留测试中的错误

字幕转换候选仍在 `test_dfxp2srt` 和 `test_parse_dfxp_time_expr` 失败，包括缺失时间返回值不正确以及把 None 传入时间格式化。复核报告说没有发现问题。这两项在保留测试中，不回传模型；A、B、C 最终都失败。它直接说明“复核说正确”不等于通过真实检查。

### 补充：youtube-dl-7 的转义处理

这题初稿失败，两个复核阶段均声称没有发现问题。带复核组第一次返工仍失败，第二次耗尽 32,768 输出 tokens，返回 incomplete/output_limit；它没有交出通过结果。仅测试返工组最终结果为：失败。这题没有因耗时长或失败而从统计中删除。

不完整输出计为未交付通过结果，保留测试栏也计为未通过；这不等于已经执行了一份错误修改并造成回归。

## 限制与结论边界

- 37/46 题的原始缺陷能被保留测试揭示；其余题的保留测试主要用于检查回归。因此同时报告完整套件与保留测试，不能只看保留测试总分。
- QuixBugs 是公开且较短的算法题，可能被训练数据覆盖。这轮基线接近满分，测量提升存在明显上限；不代表大型仓库、多文件设计、异步并发和需求澄清的表现。
- 单次、非种子固定、共享推理服务器环境的描述性试验，不足以估计稳定胜率或宣称统计显著。没有为了得到正向结果筛掉失败题，也没有给任一组提供官方修复。
- 当前 B 是保守的“测试确认后返工”流程，没有让另一个大模型替复核器确认新反例；不能推导人工强主控或完整 GVS5H 原版框架的收益。
- 测试通过只说明这些测试通过，不保证不存在遗漏错误。本轮不支持对所有简单修改强制增加一次复核；真实测试与按失败返工的价值更直接。
